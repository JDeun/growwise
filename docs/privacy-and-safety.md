# 개인정보와 안전 원칙

GrowWise는 아동의 장기 기록을 다루는 도구이며 저장소는 공개(public)다. 개인정보 보호뿐
아니라 **과도한 관찰·점수화·발달 진단·AI 과잉해석을 막는 것**도 제품 안전의 일부다.

## 제품 안전 원칙

- 아이에게 직접 사용할 생성 자료는 **부모 또는 교사 검토를 기본값**으로 둔다.
- 아이를 점수·등수·낙인으로 환원하지 않는다.
- 객관적 학업 측정치는 필요할 때 저장할 수 있지만 아이의 전인적 가치나 잠재력으로
  일반화하지 않는다.
- 평가보다 관찰, 다음 활동, 관심 변화와 맥락을 중심으로 기록한다.
- 기록량 자체를 성과로 만들지 않는다. 기록 공백은 실패가 아니다.
- 영아·발달 관찰을 진단·정상/비정상 판정·또래 percentile에 사용하지 않는다.
- 사진, 음성, 위치, 실명 정보는 기본 비공개(로컬 전용)로 둔다.
- 외부 API로 전송되는 데이터는 최소화한다.
- AI의 추천·요약은 부모의 판단보다 아래에 있으며, 근거와 불확실성을 표시한다.

## 최소 기록·비감시 원칙

GrowWise는 육아 ERP나 상시 감시 시스템을 목표로 하지 않는다.

- 부모가 다음 판단이나 기억에 가치가 있다고 선택한 사건을 중심으로 기록한다.
- 모든 행동·식사·감정·놀이를 자동 수집하는 기능을 기본값으로 만들지 않는다.
- 센서·사진·음성 등 고밀도 데이터는 기능상 명확한 필요와 별도 동의가 없으면 수집하지
  않는다.
- streak, daily completion rate, "오늘 기록 없음" 경고처럼 기록을 강제하는 dark pattern을
  두지 않는다.
- 장기 분석에서 **missing data를 부정적 상태로 해석하지 않는다.** "관찰되지 않음"과
  "하지 못함"을 구분한다.

## 발달·건강 경계

특히 `INFANT_0_2`와 유아 단계에서 다음을 금지한다.

- 저장된 관찰만으로 발달 지연·장애·질환을 추정하거나 진단
- 정상/비정상, 합격/미달 같은 판정
- 또래 대비 백분위·순위·발달 나이 산출
- 경험 커버리지 부족을 발달 부족으로 표현

발달 관련 정보는 **관찰 힌트와 활동 맥락**으로만 사용한다. 사용자가 건강·발달 우려를
직접 제기하더라도 제품은 전문 평가를 대체하지 않는다.

## 데이터 처리 원칙

1. **로컬 우선(local-first)**: 아동 프로필·학습 기록·생성물·음성은 데스크탑 로컬에
   저장하며, 외부 전송을 기본값으로 삼지 않는다.
2. **경계 통제**: 외부 자료 접근은 `adapters/` 계층으로만 한다. 어댑터 요청에는 아동 식별
   정보를 포함하지 않는다.
3. **최소 수집**: 기능에 꼭 필요한 정보만 다룬다. 정확한 생년·주소·연락처는 기본 도메인
   요구사항이 아니다.
4. **검토 게이트**: 생성물은 자동 안전/grounding 검사와 Parent Review를 거쳐 사용한다.
5. **목적 제한**: 한 목적으로 수집한 민감 데이터를 다른 분석 기능에 자동 재사용하지 않는다.

## 모델·저장·전송 프라이버시 (구현 계약)

"로컬=비공개"라는 가정은 동기화·원격모델·내보내기까지 봐야 진짜다([threat-model.md](threat-model.md)).

- **Model Provider egress 계약**: 기본 text provider는 loopback/local이다. OpenAI-compatible
  비-loopback endpoint는 `GROWWISE_MODEL_REMOTE_ALLOWED=true`를 명시적으로 켜야만 생성되며,
  API key를 사용하는 원격 endpoint는 HTTPS만 허용한다. 자료 생성 시 단계·월령·관심사와
  일반화된 generation guidance가 모델 입력에 포함될 수 있으므로 이 opt-in은 실제 외부 전송 동의
  경계다. 이름·닉네임·사진 원본은 material prompt에 넣지 않는다.
- **Embedding endpoint 분리**: text provider URL과 embedding URL을 공유하지 않는다. 원격 text
  provider를 선택해도 RAG embedding은 `GROWWISE_EMBEDDING_BASE_URL`의 별도 local endpoint를
  그대로 사용한다.
- **사진 모델 egress**: 사진 기능의 text/vision provider는 loopback endpoint를 기본으로
  사용한다. 원격 endpoint는 각각 `photo_remote_text_allowed`,
  `photo_remote_vision_allowed`를 명시적으로 켠 경우에만 허용한다.
- **데이터 최소화 RAG**: 자연어 질의가 전체 아동 기록을 무조건 프롬프트에 넣지 않는다.
  child scope, 기간, entity type, relevance로 필요한 최소 context만 선택한다.
- **저장 위치**: 아동 데이터는 앱 전용 경로(OS app-data)를 기본으로 하고 동기화 폴더 사용
  시 사용자에게 경고한다. 선택적 at-rest 암호화를 제공한다.
- **내보내기 리댁션**: Markdown bundle/PDF 공유 시 실명·관찰·위치 등 민감 필드를 선택적으로
  제거할 수 있게 하고 목적지 위험을 알린다.
- **탐방 위치**: 집 주변 좌표는 식별정보로 취급한다. 좌표 coarsening 또는 사용자 입력
  장소를 우선한다.
- **API 키**: OS 키체인/자격증명 저장소를 사용하고 저장소에 커밋하지 않는다.
- **외부 콘텐츠**: 웹·도서·지도 텍스트는 데이터로만 취급하고 명령으로 실행하지 않는다.
  prompt injection과 malicious document를 별도 threat로 다룬다.
- **Public HTTP trust boundary**: public-data adapter는 HTTPS만 허용하고 redirect가 원래 HTTPS
  origin을 벗어나거나 downgrade되면 요청을 중단한다. credential이 포함된 요청을 다른 origin으로
  따라가지 않는다.

## 해석 안전성

LLM이 장기 기록을 요약할 때는 다음을 지킨다.

- **관찰과 추론을 구분**해서 표시한다.
- 근거가 없는 성격·능력·발달 특성 추론을 만들지 않는다.
- 소수 사건을 장기적 특성으로 일반화하지 않는다.
- 기록 공백을 부정적 근거로 사용하지 않는다.
- 부모의 기존 신념을 자동으로 강화하지 않는다. 반대되는 관찰이나 불확실성이 있으면 함께
  보여준다.
- "최근 기록상", "관찰된 범위에서는"처럼 데이터 범위를 명시한다.

## Learning Wiki 안전 경계

장기 기록을 연결하는 Learning Wiki는 **AI가 아이에 대해 만든 새로운 사실 저장소**로 취급하지
않는다.

- Wiki는 원본 child record의 파생 문서이며 언제든 원본만으로 rebuild할 수 있어야 한다.
- 각 합성 항목은 실제 원본 source ref를 유지한다.
- 기존 Wiki를 다시 evidence로 사용하지 않아 잘못된 추론의 자기강화 loop를 만들지 않는다.
- 단일 사건을 고정된 흥미·능력·성격으로 일반화하지 않는다.
- 진단, 정상/비정상, 또래 비교와 같은 문구는 model output validation에서 제거한다.
- 대화/자료 생성이 Wiki를 사용해도 원본 record와 parent judgment가 우선한다.
- 아이 삭제 시 Wiki도 child-owned live data로 함께 제거한다.

## 저장소(repo) 규칙

공개 저장소에는 **실제 아동 데이터를 절대 커밋하지 않는다.**

- 커밋 금지: 실명, 생년월일, 주소/거주지, 사진, 음성 원본, 개인 연락처, 실제 학습 기록,
  관찰 메모, 채워진 `child_profile`.
- 저장소에는 스키마·빈 예시·합성 데이터만 둔다.
- 실제 데이터 경로(`data/`, `storage/`, `learning_logs/`, `generated/`, `*.db` 등)는
  `.gitignore`로 제외한다.
- 비밀정보는 저장소에 올리지 않는다. 공유 설정은 값 없는 example만 제공한다.
- 저장소 감사 테스트는 전화번호·주민등록번호 형태를 항상 검사한다. 프로젝트 고유 실명 등은
  GitHub Actions secret `GROWWISE_PII_DENYLIST`에 쉼표 구분으로 넣어 CI에만 주입한다.
  값 자체를 workflow·fixture·문서에 커밋하지 않는다.

## 커밋 전 체크리스트

- [ ] 실제 아동의 식별정보·사진·음성이 포함되지 않았는가?
- [ ] 실제 학습/관찰 기록이 아니라 합성 fixture인가?
- [ ] 키·토큰·비밀번호가 포함되지 않았는가?
- [ ] 새 데이터 경로가 `.gitignore`에 반영됐는가?
