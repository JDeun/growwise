# 아이·기간별 원본 기록 내보내기

**백업 및 복원 → 선택 기록 내보내기**에서 아이와 시작일·종료일을 고르고 ZIP을 저장한다.
날짜는 선택 사항이며 양 끝 날짜를 포함한다. 비워 둔 쪽에는 날짜 제한이 없다. 기록 날짜는
`occurred_at`을 우선하고, 이전 기록은 `created_at`을 사용한다. 날짜 경계는 Core가 실행되는
기기의 현지 시간대다.

이 ZIP은 원본 Markdown과 필요한 managed asset을 옮겨 읽기 위한 묶음이다. 원문을 비식별화하거나
암호화하지 않는다. 이름·관찰·사진 등 개인정보가 포함되므로 저장 위치와 전달 대상을 확인한다.
복원 가능한 전체 백업이 필요하면 기존 **백업 만들기/백업 내보내기**를 사용한다.

## 포함 범위

- 선택한 아이에게 현재 보이는 원본 기록 중 기간에 해당하는 기록.
- 선택한 아이의 프로필은 생성일과 관계없이 포함한다.
- 선택 기록이 참조하는 현재 허용된 책·자료·활동·사진 및 프로필 사진은 기간 밖이어도 근거를
  보존하기 위해 포함한다. 따라서 날짜 선택이 모든 첨부·참조 기록의 날짜를 제한하지는 않는다.
- 현재 전체 아이와 공유한 참고 자료와 명시적으로 공유된 원본은 포함될 수 있다. 다른 아이의
  비공개 원본이나 프로필은 포함하지 않는다. 공유 철회와 소유권은 내보내기 시점의 Markdown
  원본에서 다시 확인한다.
- 파생 Learning Wiki, 작업 큐/워크플로 실행 기록, 대화 DB, SQLite 인덱스, 이전 백업, API 키는
  포함하지 않는다. 필요한 연결은 양 끝 원본이 묶음에 있을 때만 포함한다.

기록은 재직렬화하지 않고 원본 `.md` 바이트 그대로 보존한다. 첨부는 기존 `assets/` 상대 경로를
유지하며, 저장된 크기와 SHA-256을 확인한다. 동시 저장·공유 철회·삭제·복원과 엇갈리지 않도록
내보낼 snapshot을 만드는 동안 쓰기를 잠시 막는다.

## 파일 형식과 복원 경계

ZIP의 `records/<entity_type>/<id>.md`, `assets/<relative_path>`와
`growwise-record-export.json`에 선택 범위·생성 시각·파일 SHA-256을 기록한다. manifest의
`supporting_record_ids`는 기간 밖 참조 등 보조 기록을 구분한다.

`growwise-record-export.json`은 전체 백업의 `manifest.json`과 다르다.
`full_backup: false`, `restorable_by_app: false`이며, 앱의 전체 백업 가져오기/복원은 이 ZIP을
거절한다. 일부 아이의 내보내기를 전체 snapshot으로 오인해 다른 아이의 데이터를 덮어쓰는
부분 복원 기능은 제공하지 않는다.

## 제한과 오류

Core API는 인증된 `GET /v1/children/{child_id}/records/export`이며, 선택적인 `start_date`,
`end_date`는 `YYYY-MM-DD` 형식이다. 응답은 `application/zip`, 파일명은
`growwise-records-YYYY-MM-DD.zip`이다. Desktop은 다운로드를 마친 뒤 저장 대화상자를 열며,
취소하면 임시 파일을 지운다. 응답 완료·연결 중단 후 Core의 임시 ZIP도 지운다.

묶음은 최대10,000항목, 파일당64MiB, 전체 비압축512MiB, ZIP600MiB로 제한한다. 원본 전체
탐색도100,000기록/512MiB, 생성은120초로 제한한다. 선택한 아이의 기록이 작아도 전체 원본
탐색 한도를 넘으면 분할이나 정리가 필요하다. 시작·종료일을 모두 지정하면 역순 또는36,600일
초과 구간을 거절한다. 원본 오류를 숨긴 불완전한 묶음을 만들지 않는다.

| HTTP | 의미 |
| --- | --- |
| 400 | 역순/과도한 날짜 구간 (`invalid_export_period`) |
| 404 | 존재하지 않는 아이 (`child_not_found`) |
| 409 | 손상·누락·안전하지 않은 원본/첨부 (`records_export_unavailable`) |
| 413 | 크기·개수·생성 시간 제한 (`records_export_too_large`) |
| 422 | 잘못된 UUID/날짜 형식 |
| 503 | 다른 데이터 정비 작업 진행 중 |

심볼릭 링크·junction·관리 경로 밖 파일·일치하지 않는 첨부 소유권/해시는 거절한다. 한계를
우회하기 위해 임의 파일 경로나 외부 URL을 받아 ZIP에 넣지 않는다.

`tests/test_records_export.py`는 실제 API에서 원본 바이트·기간·공유 철회·첨부·경로와 한도·
임시 파일 정리·부분 복원 거절을 검증한다. 실제 UI 저장 흐름은 [최종21단계 관측](knowledge/experiments/live-core-browser-20261103-verified.md)에서 검증했다.
