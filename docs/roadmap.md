# 로드맵

## 제품화 단계

| 단계 | 형태 | 핵심 결과물 |
| --- | --- | --- |
| **1단계** | 개인용 홈서버 도구 | 자료 생성 + 학습 기록장(부모 직접 사용) |
| **2단계** | 교사용 자료 생성기 | 주제·연령·시간·목표 입력 → 수업안·활동지 |
| **3단계** | 기관용 설치형/SaaS | 개인정보 보호, 원내 배포, 교사 워크플로우, 학부모 커뮤니케이션 |

## 미해결 설계 질문

첫 마일스톤을 확정하기 전에 결정해야 하는 것들이다.

1. **개인용 우선 vs 템플릿 엔진 우선** — 개인용 MVP를 먼저 만들 것인가, 기관용 확장을
   전제로 처음부터 템플릿 엔진을 설계할 것인가?
2. **기록 저장 방식** — 학습 기록을 Obsidian/Markdown 중심으로 둘 것인가, 별도 SQLite
   기반 앱 데이터로 둘 것인가?
3. **첫 활동지 카테고리** — 독서, 영어, 탐방 중 무엇으로 시작할 것인가?
4. **기관용 파일럿 대상** — 어린이집, 유치원, 학원 중 어느 워크플로우가 가장 현실적인가?
5. **로컬/외부 경계** — 외부 API를 어디까지 허용하고, 어떤 데이터는 반드시 로컬에만
   둘 것인가?

## 첫 마일스톤 제안 (M0)

설계를 코드로 바꾸기 위한 최소 목표를 다음과 같이 제안한다. (확정 아님 — 위 질문을
먼저 정한 뒤 조정)

- [ ] 기술 스택 고정: 백엔드(FastAPI vs Node), 저장(SQLite vs Markdown), RAG 여부
- [ ] 데이터 모델 v0 스키마 확정([data-model.md](data-model.md))
- [ ] 첫 생성 모듈 1종 구현(예: 독서 활동지) — 라우터 → 생성 → 저장 → PDF 출력 end-to-end
- [ ] Parent Review Layer 최소 구현(노출 전 체크리스트)
- [ ] 학습 로그 저장/조회
- [ ] 로컬 실행 가이드(README 보강)

## 검증 지점

제품으로 발전시키려면 다음 네 가지가 핵심 검증 지점이다([vision.md](vision.md) 참고).

1. 교육과정 기준(누리과정·초등 교육과정 매핑)
2. 현장 교사 워크플로우
3. 개인정보 설계([privacy-and-safety.md](privacy-and-safety.md))
4. 출력 품질(인쇄 가능한 활동지)
