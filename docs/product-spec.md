# 제품 사양

## 개요

growwise는 세 겹의 사용자 가치를 가진다.

1. **자료 생성** — 입력(책·연령·목표·장소 등)을 받아 활동지·카드·질문·수업안을 만든다.
2. **학습 기록** — 활동 후 아이의 반응·어려움·흥미·다음 활동을 남긴다.
3. **부모 검토** — 아이에게 보여주기 전 난이도·민감성·개인정보를 점검한다.

주 사용자는 아이가 아니라 **부모(개인용)와 교사(기관용)**다.

> **현재 우선 목표: 개인이 운영하는 홈스쿨링용 데스크탑 앱(Windows·macOS).** 부모 한
> 명이 데스크탑에 설치해 쓰는 형태가 1차 목표다. 홈서버·상시 백엔드는 목표가 아니며,
> 기관용(어린이집·유치원·학원) 확장은 그 뒤로 미뤄 둔다. 아래 기관용 내용은 나중 단계를
> 위한 참고다.

## 대상 연령과 단계별 역할

growwise는 **0세(영아)부터 고등학교까지** 아이의 성장을 함께하는 도구다. 단, 연령마다
"돕는 방식"이 완전히 달라진다. 어느 단계에서도 **아이 대면 챗봇은 없고**, 부모(및 나중
기관의 교사)를 돕는 조수로 동작한다.

| 단계 | 연령(대략) | 교육과정 기준 | growwise의 역할 |
| --- | --- | --- | --- |
| **영아** | 0~2세 | 표준보육과정(0~2세) | **부모 대면**: 발달 이정표·연령별 놀이/상호작용 제안·**책 읽어주기(보드북) 추천**·관찰 기록. 아이 화면·워크시트 없음 |
| **유아** | 3~5세 | 누리과정 | 놀이형 활동지·독서·탐방·수학놀이 **생성** + 학습 대화 기록 |
| **초등** | 6~12세 | 초등 교육과정 | 과목별 활동지·독서·탐방·과학·글쓰기 코치 **생성** + 기록 (핵심 기능대) |
| **중등** | 중학교 | 중학 교육과정 | **직접 자료 생성보다 학습 트래킹·보조**: 진도·약점 지도(weakmap)·오답·회고·자원 추천·**부모가 도와줄 지점** 정리 |
| **고등** | 고등학교 | 고교 교육과정 | 동일하게 **트래킹·보조**. 시험 대비 학습 그래프는 PAIDEIA식 `수집→분석→약점지도→회고` 참고([references.md](references.md)) |

**핵심 원칙(연령 불문)**

- **직접 교육이 아니라 보조·기록**이 본질이다. 특히 중·고는 아이를 대신해 가르치거나
  답을 주지 않고, **아이의 학습을 추적하고 부모가 도울 수 있게** 한다.
- 아이 대면 AI 대화는 전 연령에서 범위 밖(§"아이 대면 AI 없음").
- `child_profile.stage`가 이 단계를 담아, 생성물·기록·부모 안내를 단계에 맞게 바꾼다.
- **전 연령 완성이 목표**이며, 구현 순서는 로드맵을 따른다(현재 착수=탐방, 유아·초등대).

## 개인용 MVP

첫 버전은 **학습자료 생성기 + 학습 기록장** 정도가 적절하다.

### 핵심 기능

| 기능 | 입력 | 출력 |
| --- | --- | --- |
| 독서 활동지 생성 | 책 제목, 연령, 목표 | 질문, 어휘, 말하기 주제, 그림/쓰기 활동 |
| 영어 대화 카드 생성 | 일상 상황 | 짧은 영어 문장, 부모-아이 롤플레이, 반복 표현 |
| 탐방/여행 활동지 생성 | 장소, 역사 사건, 시설, 여행지 | 관찰 미션, 질문 |
| 수학 놀이 활동 생성 | 개념(수·패턴·분류·비교·측정·도형) | 놀이형 활동 |
| 글쓰기·말하기 코치 | 아이의 답변 | 다음 질문, 표현 확장, 다시 말하기 활동 |
| 학습 로그 저장 | 활동 결과 | 날짜·자료·반응·어려움·다음 활동(Markdown/DB) |
| 부모 검토 체크리스트 | 생성물 | 난이도·민감성·평가 압박·개인정보 노출 점검 |

### MVP 범위 원칙

- 단순한 라우터 하나로 입력 유형을 보고 해당 생성 모듈로 보낸다(멀티에이전트 지양).
- 인터넷 연결 없이도 기본 자료 생성과 기록 조회가 가능해야 한다.
- 출력은 부모가 바로 인쇄할 수 있는 품질(PDF)을 목표로 한다.

## 사상을 제품 요건으로 (핵심)

[pedagogy.md](pedagogy.md)의 원칙을 "지켜야 할 제품 요건"으로 못박는다. 이 네 가지가
growwise를 일반 자료 생성기와 구분하는 지점이다.

### 1. 학습 대화 로그가 중심 데이터

핵심 산출물은 완성된 활동지가 아니라 **아이의 질문·풀이 과정·AI 힌트·부모 관찰·검증
근거·자기 언어 재구성**이다. 스키마는 [data-model.md](data-model.md)의 `learning_log`
상세를 따른다. 점수·낙인 필드는 두지 않는다.

### 2. 부모 검토 계층 (노출 전 필수 게이트)

생성물은 아이에게 보여주기 전 반드시 부모 검토를 거친다. 상태 흐름:

```
생성 → [검토 대기] → 부모 검토 → 승인 | 수정요청 | 폐기
                                  └ 승인분만 아이에게 노출·기록
```

검토 체크리스트(기본):

- 난이도가 아이 단계에 맞는가
- 민감·부적절 내용은 없는가
- 평가·정답 압박을 주지 않는가
- 개인정보 노출은 없는가
- **정답을 대신 주지 않고 스스로 하게 남겼는가**(아래 3)
- 연령·발달 적합성

`parent_review`에 검토 결과·수정사항을 남긴다. 검토 없이는 노출·기록되지 않는다(기본값).

### 3. 과도한 도움 경계 (scaffold ≠ 정답 대납)

코치·생성 모듈은 **"언제 돕고 언제 물러설지"**를 설계 요건으로 삼는다(TutorMoments,
[references.md](references.md)). LLM은 기본적으로 답을 너무 많이 주므로:

- 코치는 정답을 바로 주지 않고 **힌트를 하나씩** 제공하는 것을 기본 모드로 한다.
- 프롬프트에 scaffold/rigor 트레이드오프를 명시한다.
- `learning_log.ai_hint`에 "얼마나 스스로 하게 남겼는가"를 기록해 개선에 활용한다.

### 4. 아이 대면 AI 없음 — 단계적 노출은 콘텐츠로

"비판적 사고가 서기 전 AI를 정답 기계로 접하지 않는다"([pedagogy.md](pedagogy.md))를
가장 확실하게 지키는 방법: **growwise 안에는 아이가 대화하는 챗봇을 두지 않는다.**

- **범위 제외**: 아이-AI 직접 대화는 이 앱의 기능이 아니다(필요하면 기존 상용 서비스를
  쓴다). AI는 **부모·교사를 돕는 조수**로만 동작한다 — 자료 생성·기록·검토 보조.
- 따라서 앱 안에 "아이 대면 AI를 여닫는 게이트"는 없다. 대신 `child_profile.stage`와
  `ai_exposure_level`은 **생성되는 콘텐츠와 부모 안내를 조절**하는 데 쓴다(예: 단계가
  되면 "AI 사용 5규칙" 연습 활동을 부모가 아이와 함께 하도록 자료를 만들고, 그 회고를
  `learning_log`에 남긴다).
- 즉 단계적 AI 노출은 "앱이 아이에게 챗봇을 열어주는" 방식이 아니라, **부모가 아이의
  AI 사용을 어떻게·언제 이끌지**를 돕는 자료·기록으로 실현한다.

## 기관용 확장

잘 만들면 개인용 도구를 넘어 유치원·어린이집·학원·방과후 교실에서 쓰는
**교사용 AI 자료 제작 시스템**으로 발전할 수 있다. 기관용 포지셔닝은 아이 개인
튜터보다 **교사용 수업자료 제작 시스템**에 가깝다.

### 기관용 핵심 기능

- 연령별 활동지 생성
- 누리과정 및 초등 저학년 교육과정 매핑
- 주제별 수업안 생성
- 가정 연계 활동지 및 안내문 생성
- 학부모 피드백 문서 생성
- 아이 반응 관찰 기록 템플릿
- 반 전체 수준에 맞춘 난이도 조절
- 같은 주제를 언어·수학·과학·사회·미술·신체 활동으로 변환

## 제품화 3단계

| 단계 | 형태 | 중요 포인트 |
| --- | --- | --- |
| **1단계 (현재 목표)** | 개인용 데스크탑 앱 | 부모가 직접 쓰는 자료 생성과 학습 기록 |
| **2단계** | 교사용 자료 생성기 | 주제·연령·수업 시간·활동 목표 입력 → 수업안·활동지 |
| **3단계** | 어린이집·유치원·학원용 설치형/SaaS | 개인정보 보호, 원내 서버 배포, 교사 워크플로우, 학부모 커뮤니케이션 |

단계별로 재구조화 없이 성장하도록, 데이터 모델과 모듈 경계를 처음부터 개인용/기관용
공용으로 설계한다([data-model.md](data-model.md), [architecture.md](architecture.md) 참고).

## 비기능 요구사항

- **크로스플랫폼**: Windows·macOS 데스크탑 지원(Tauri). 처음부터 양 OS를 함께 빌드·검증
- **오프라인 우선**: 데스크탑 앱에서 인터넷 없이 기본 기능 사용 가능(외부 API는 선택적 보강)
- **인쇄 품질 출력**: 활동지 PDF는 교사·부모가 바로 인쇄 가능해야 함
- **개인정보 보호**: 아동 데이터 로컬 우선, 외부 전송 최소화([privacy-and-safety.md](privacy-and-safety.md))
- **모델 독립성**: 특정 AI 모델/공급자에 종속되지 않고 언제든 교체·이식 가능(로컬 기본, 설정 주도). [architecture.md](architecture.md) 모델 공급자 추상화
- **확장성**: 새로운 과목·활동 유형을 생성 모듈 추가만으로 확장
